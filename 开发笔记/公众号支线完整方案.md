# 公众号支线 — 完整方案

> 对应里程碑：第三章 `wechat_public` / `wechat_articles_200` | 状态：待实现
> **命名说明：** 游戏功能名称统一用"公众号"，剧情叙述中可提及"微信"（历史事实陈述属于合理使用）。

## 一、设计意图

公众号是第三章的一条长线支线。玩家在 2012 年通过任务开通后，可以在日程中安排"运营公众号"。

**核心设计意图：这是一个体力的陷阱。**

- 运营一次公众号消耗 **25 体力**（远高于网站维护的 10~15），接近写一篇正经博客
- 但公众号带来的收入**远低于**博客广告分成，粉丝增长也十分缓慢
- 玩家亲自运营一段时间后，自然会意识到：**把体力花在公众号上不如专注博客** — 从而回归博客主业

这不是说教，而是通过 gameplay 让玩家自己悟出来的道理。

另外，公众号的运营节奏和博客不同：博客靠 SEO 和友链带来流量，公众号是封闭平台，涨粉靠的是坚持发文（200 篇后才算有起色）。这种对比也让玩家体会不同平台的特性。


## 五、核心算法

### 5.1 运营当天（一次执行）

```
运营公众号（每日限1次，耗25体力）
        │
  从 blogger.posts 中筛选：
      date == 当天 && post_category ∉ ["出版畅销书", "开源项目"]
        │
        ├── 无匹配文章 → 提示"今天没有可同步的文章"，返回 0 EXP，不消耗体力
        │
        └── 有匹配文章（可能多篇）
                │
                for each 匹配文章:
                  ① 算基准阅读量
                  ② 算14天总阅读量（含衰减权重）
                  ③ 5%爆款判定（玄学涨粉）
                  ④ 累加阅读量数据
                  ⑤ 付费文章单独算收入
                │
            汇总提示："同步了 N 篇文章，获得 M 阅读，涨粉 X"
```

### 5.2 阅读量公式

依赖两个已有数据：`article.views（文章本站阅读量）` + `wechat_data.followers（公众号粉丝数）`

```
基准 = max(1, 文章本站阅读量) × 0.15 + 粉丝数 × 0.03

14天总阅读 = int(基准 × 3.5)    ← 3.5 = 14天总衰减权重系数
```

#### 衰减权重说明（不逐日追踪，一次性算完）

| 天数 | 日占比 | 说明 |
|------|--------|------|
| 第1天 | 30% | 推送当天，阅读高峰 |
| 第2天 | 20% | 仍有曝光 |
| 第3天 | 15% | 开始下滑 |
| 第4天 | 8% | 下滑明显 |
| 第5天 | 6% | — |
| 第6天 | 5% | — |
| 第7天 | 4% | — |
| 第8-13天 | 各2~1% | 长尾 |
| 第14天 | 0% | 基本归零 |
| **合计** | **≈100%** | → 一次性乘以固定系数 **3.5** |

> 3.5 的来源：14天里第1天占30%，第14天接近0%，日均约7%，14天和 ≈ 3.5倍第1天。运营当天一次性算完，不逐日追踪。

### 5.3 爆款机制（玄学）

```
if randf() < 0.05:   ← 5% 概率
    爆款倍数 = randi_range(3, 8)
    14天总阅读 *= 爆款倍数
    涨粉 = int(14天总阅读 × randf_range(0.01, 0.03))
```

非爆款时：每篇文章涨粉 `randi_range(0, 2)`

### 5.4 付费文章收入

```
if article.is_money:
    额外收入 = int(粉丝数 × 0.005) × max(1, 文章本站阅读量) × 0.01
    立即入账（直接加到 blogger.money）
```

### 5.5 经验值

```
EXP = sum(每篇同步文章的 14天总阅读量 × 0.02)
```

## 六、数值设计

公众号的核心数据生成逻辑，模拟真实订阅号的特征：**打开率低、涨粉慢、偶尔出爆款、收入靠流量主。**

### 每次运营

```
文章数 +1
```

### 收入（月末结算）

公众号的收入来自**流量主**（文中广告），按阅读量计算 CPM，远低于博客广告：

| 条件 | 月收入公式 | 参考值 |
|------|-----------|--------|
| 文章 < 50 篇 | 0 | 无收入 |
| 文章 ≥ 50 篇 | 月累计阅读量 × 0.002~0.005 | 几百阅读 ≈ 一两元 |
| 文章 ≥ 200 篇 | 月累计阅读量 × 0.003~0.008 | 几万阅读 ≈ 几十元 |

**月末结算逻辑：**

```
月末触发 _settle_wechat_monthly_income():
    if total_articles < 50:  return 0

    cpm = 0.002  if total_articles < 200
          0.004  if total_articles >= 200

    月收入 = weekly_views × cpm
    clamp(0, 999)

    累加 total_income，weekly_views 归零
```

### 完整示例（估算）

| 累计文章 | 粉丝数 | 日均阅读 | 月收入 |
|---------|-------|---------|-------|
| 50 | ~100 | ~10 | ≈ 0~1 元 |
| 100 | ~200~300 | ~20~60 | ≈ 2~5 元 |
| 200 | ~500~800 | ~50~200 | ≈ 10~30 元 |

**与博客对比：** 同期认真写博客，广告收入轻松上百元/月。差距一目了然。

### 关于"公众号运营方式与博客不同"

公众号的操作**在日程中跟网站维护放在一起**，玩家每次选它时消耗 25 体力（比写博客还多），但得到的回报微乎其微。这种安排本身就在传达：公众号是"维护性质"的活儿，不是核心创作。玩家尝试几次后自然会得出判断。

## 八、里程碑判定

公众号支线涉及**两个**里程碑（`StoryProgress.gd` 第三章）：

| 里程碑 | 含义 | 触发方式 | 触发动作 |
|-------|------|---------|---------|
| `wechat_public` | 公众号**开通** | 时间触发任务（2012 年） | `SET_STORY_MILESTONE(chapter=3, milestone="wechat_public")` |
| `wechat_articles_200` | 公众号**累计 200 篇** | `operate_wechat()` 内检测 `total_articles >= 200` 时触发 | 通过 TaskConfig `CUSTOM` 条件 + `SET_STORY_MILESTONE` |

200 篇达成后玩家仍可继续运营公众号（少量持续收入），但不强制。

## 九、与旧模式对比

| 维度 | 旧模式（纯计数器） | 新模式（文章同步） |
|------|-------------------|-------------------|
| 文章来源 | 每次运营 +1 假计数 | 当天已发布的选中分类博文 |
| 阅读量公式 | 粉丝数 × 随机打开率(3~12%) | 博文本站阅读量 × 0.15 + 粉丝数 × 0.03 |
| 付费文章 | 无特殊处理 | 额外收入公式 |
| 14天衰减 | 无 | 一次性 ×3.5 系数模拟 |
| 玩家决策 | 无（每天点即可） | 无（每天点即可，自动同步当天所有文章） |
| 数据存储 | 计数器 | 仅多一个分类列表 |

## 十、边界情况处理

| 情况 | 处理方式 |
|------|----------|
| 当天发了 0 篇匹配文章 | 运营时提示"今天没有可同步的文章"，不消耗体力，返回 0 |
| 当天发了 5 篇匹配，其中 1 篇付费 | 4 篇免费算阅读量，1 篇付费单独计算收入 |
| 当天发表的文章包含"出版畅销书"或"开源项目" | 自动跳过，不纳入公众号同步（公众号不支持这些类型） |
| 运营时文章已归档（大于84天） | 不可能发生，因为只查当天的文章 |
| 同一篇文章等级变化 | 不可能，`article_level` 发布时固定 |
